Разделено на две части:

- **Часть A — отклонения от подтверждённых правил.** Правило установлено
  подсчётом по коду, конкретные места из него выбиваются.

# Часть A. Отклонения от правил

## A-1. Недопустимые значения `color`

**Правило.** Валидны только `primary`, `secondary`, `success`, `info`,
`warning`, `error`, `neutral` (`@nuxt/ui/dist/shared/ui.*.mjs:57-59`:
дефолтный набор + `neutral`; проект список не расширяет).

**Отклонение.** `color="red"` (8) и `color="amber"` (3) — такие значения не
сопоставляются ни с одним вариантом, компонент остаётся без цветовых классов.

| Файл | Строки |
|------|--------|
| `src/components/tests/FormPreview.vue` | 25 (`amber`), 38 (`red`) |
| `src/components/tests/FormTake.vue` | 144 (`amber`), 176, 254 (`red`) |
| `src/components/tests/FormReport.vue` | 155 (`red`) |
| `src/components/tests/QuestionEditor.vue` | 100, 171 (`red`) |
| `src/pages/Admin/AdminDashboardPage.vue` | 1243 (`red`) |
| `src/pages/Events/EventDetailsPage.vue` | 824 (`red`) |
| `src/pages/TestsPage.vue` | 100 (`amber`) |

Соответствие: `red` → `error`, `amber` → `warning`.

**[ПОДТВЕРЖДЕНО]**

## A-2. Жёстко заданные цвета палитры вместо семантических токенов

**Правило.** Цвет задаётся семантическими токенами (`text-muted` 238,
`text-highlighted` 173, `bg-elevated` 98 и т. д.).

**Отклонение.** 65 вхождений прямых классов палитры. Они не следуют за выбранной
пользователем темой.

| Файл | Что |
|------|-----|
| `src/pages/Tests/QuestionsBuilder.vue` | `ring-green-500`, `bg-green-500`, `text-green-600/400` |
| `src/pages/Tests/TestRunner.vue` | `bg-red-500`, `ring-red-500`, `text-red-600/400` |
| `src/pages/Tests/StatsDetail.vue` | зелёный/красный для верных и неверных ответов |
| `src/pages/Courses/admin/CourseResultsPage.vue` | цвета статусов |
| `src/components/KioskAside.vue` | `text-zinc-50`, `bg-neutral-900`, `text-neutral-50` |

Отдельно: `src/composables/useCalendarFeed.ts:43-49` — источник `event`
закодирован как `bg-emerald-500/15 text-emerald-400 …`, тогда как соседние
источники (`meeting`) уже используют семантический `info`. То есть внутри одного
объекта два подхода.

Замечание: часть случаев осмысленна — «верно / неверно» в тестах должно
оставаться зелёным и красным независимо от темы. Но тогда это `success` и
`error`, а не `green-500` и `red-500`.

**[ПОДТВЕРЖДЕНО]**

## A-3. Два разных экрана «Раздел в разработке»

**Правило.** Для этого есть компонент `SectionInDevelopment.vue` (карточка по

**Отклонение.** `src/pages/ApplicationsPage.vue:10-17` делает то же самое

**[ПОДТВЕРЖДЕНО]**

## A-4. Инлайновый `font-family` вместо утилиты

**Правило.** Display-гарнитура задаётся утилитой `font-unbounded`
(`--font-unbounded`, 6 файлов).

**Отклонение.** `src/pages/login.vue:79,86` —
`style="font-family: 'Unbounded', sans-serif;"`. Инлайновый стиль обходит
коррекцию весов `html[data-ui-font='unbounded']` из `tailwind.css` и не
переключается вместе с выбранным шрифтом.

**[ПОДТВЕРЖДЕНО]**

## A-5. Компонент проекта с префиксом `U`

**Правило.** Префикс `U` зарезервирован за Nuxt UI (`prefix: 'U'` в дефолтах
библиотеки).

**Отклонение.** `src/components/UContentSurround.vue` — компонент проекта.
Он попадает в `components.d.ts` вперемешку с библиотечными, и по имени его от

**[ПОДТВЕРЖДЕНО]**

**Отклонение.** `src/pages/ServicesPage.vue:300` открывается сразу `<div>`.

**[ПОДТВЕРЖДЕНО]**

## A-7. Тексты уведомлений противоречат поведению

**Правило.** Сообщение отражает то, что произошло.

**Отклонение.** `src/composables/useAppToast.ts` — `profileSaved()`,
`adminUserSaved()`, `adminOfoSaved()` содержат «(демо)» и «записаны локально»,
хотя вызываются после успешного ответа сервера.

Подробно — [known-issues.md](../known-issues.md), IMP-04.

**[ПОДТВЕРЖДЕНО]**

## A-8. Кнопки без действия

**Правило.** Интерактивный элемент что-то делает.

**Отклонения:**

# Часть B. Предложения

Правило отсутствует; ниже — наблюдения и варианты. **[ПРЕДЛОЖЕНИЕ]**

## B-1. Два подхода к валидации форм

Zod + `UForm :schema` применяется **только** на экране входа. Все остальные
формы валидируются вручную через `reactive`-объекты ошибок (`FeedbackPage.vue`
и др.), хотя Zod уже в зависимостях, а Nuxt UI поддерживает
Standard Schema из коробки.

Вариант: принять Zod + `UForm :schema` как стандарт для новых форм, старые не
переписывать.

## B-2. Три способа обращения к API

`apiSessionFetch` (Bearer), голый `fetch` (cookie) и `jsonFetch` из
`src/tests/api.ts` (cookie + рудиментарный `X-User-Id`). Общей обработки ошибок
и 401 у всех трёх нет — единый выход на `/login` реализован только в
`apiSessionFetch`.

Вариант: постепенно свести всё к `apiSessionFetch`.

## B-3. Не унифицирован вертикальный ритм секций

`gap-6` (40) — между крупными секциями, `gap-4` (93) — внутри секции, но
встречается и `gap-2`/`gap-3` на том же уровне вложенности
(например `HomePage.vue:368` — `gap-2` между секциями страницы).

Вариант: зафиксировать `gap-6` / `gap-4` / `gap-3` как три уровня и привести
новые экраны к ним.

## B-4. Фиксированные радиусы не следуют за настройкой темы

`rounded-lg` (80), `rounded-xl` (60), `rounded-3xl` (8), `rounded-2xl` (6)
не зависят от выбранного пользователем радиуса, в отличие от `rounded-panel` (56).

Вариант: для панелей и карточек использовать `rounded-panel`; фиксированные
радиусы оставить для мелких элементов (чипы, аватары).

## B-5. Объявлены, но не используются

| Что | Где объявлено | Использование |
|-----|---------------|---------------|
| `--color-brand: #50c891` | `tailwind.css:12` | 0 |
| `--breakpoint-3xl: 1700px` | `tailwind.css:5` | 0 |
| брейкпоинт `2xl` | Tailwind | 0 |
| `UContentSurround.vue` | `src/components/` | 0 |
| `@heroicons/vue` | `package.json` | 0 |

Отдельно: `--color-brand` (`#50c891`) **не совпадает** с брендовым
`--color-emerald-500` (`#00DC82`). Какое значение считать брендовым —
**[НЕИЗВЕСТНО]**.

Вариант: либо использовать, либо удалить — сейчас они вводят в заблуждение.

## B-6. `--ui-header-height` не соответствует фактической высоте

Переменная Nuxt UI по умолчанию `4rem` (64px); шапка и заголовок сайдбара —
`h-[60px]`. `main.base` в `vite.config.js` считает минимальную высоту как
`calc(100vh - var(--ui-header-height))`, то есть от 64px.

Вариант: переопределить `--ui-header-height: 60px` в `tailwind.css` либо
привести высоту к 64px.

## B-7. Нет `prefers-reduced-motion`

Анимация смены темы (600 мс кругового раскрытия) выполняется всегда. Проверено:
`prefers-reduced-motion` в `src/` не встречается.

Вариант: отключать View Transition при `prefers-reduced-motion: reduce`.

## B-8. Контраст не проверяется

18 primary-палитр × 9 neutral × 2 темы. Автоматической проверки контраста нет,
требований к уровню (WCAG AA/AAA) в проекте не зафиксировано — **[НЕИЗВЕСТНО]**.

Вариант: зафиксировать целевой уровень и проверить хотя бы сочетания по
умолчанию (emerald / zinc в обеих темах).

## B-9. Киоск как отдельная визуальная система

У киоска свои размеры (`text-3xl`, `p-6`, `rounded-3xl`, иконки `size-12`), свои
цветовые классы и своя логика темы. Это выглядит оправданным — экран большой и
смотрят на него издалека, — но нигде не зафиксировано как решение.

Вариант: описать киоск как отдельный набор правил. **Изменять киоск нельзя**
(ADR-002), поэтому речь только о документировании.

## Как пользоваться этим документом

1. Новый код пишется **по правилам**, а не по отклонениям.
2. Отклонение из части A исправляется, только когда вы и так правите этот файл
   по задаче, — и это упоминается в отчёте.
3. Массовая правка отклонений — отдельная задача с согласованием.
4. Предложения из части B **не реализуются** без решения владельца.
