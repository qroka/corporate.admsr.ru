# Состояния, валидация и обратная связь

## 1. Загрузка

### Скелетоны — основной приём

`USkeleton` используется примерно в 28 файлах. Правило: скелетон повторяет **форму
будущего контента**, а не спиннер. **[ПОДТВЕРЖДЕНО]**

Сетка карточек (`GalleryPage.vue`):

```html
<div v-if="loading" class="grid grid-cols-1 sm:grid-cols-2 lg:grid-cols-3 gap-3">
  <USkeleton v-for="i in 6" :key="i" class="h-64 rounded-panel" />
</div>
```

Различаются два вида загрузки ленты:

| Состояние | Что показывать |
|-----------|----------------|
| `initialLoading` — первая страница | 3–6 скелетонов вместо всего списка |
| `loading` — догрузка следующей | 2–3 скелетона **под** уже показанным списком |

`useCursorFeed` отдаёт оба флага отдельно (`loading`, `initialLoading`).
**[ПОДТВЕРЖДЕНО]**

Скелетоны наследуют геометрию контента: `rounded-panel` для панелей,
`rounded-full` для аватаров.

### Загрузка внутри элементов

- Кнопка действия: `:loading="submitting"` — `UButton` сам показывает спиннер и
  блокируется.
- Шапка при загрузке профиля: `USkeleton` вместо аватара и имени
  (`AppHeader.vue:340-343`).

### Флаг «идёт отправка»

Каждая форма держит собственный `ref` (`submitting`, `profileSaving`,
`groupDeleting`) и передаёт его в `:loading`, а также защищается от повторной
отправки: `if (!validate() || submitting.value) return;`
(`FeedbackPage.vue:49`). **[ПОДТВЕРЖДЕНО]**

## 2. Пусто

`UEmpty` — ~31 вхождение в ~22 файлах, **всегда `variant="naked"`**.
**[ПОДТВЕРЖДЕНО — 20 из 20 явных указаний варианта]**

```html
<UEmpty
  variant="naked"
  icon="i-lucide-images"
  title="Альбомы не найдены"
  description="Измените поиск или создайте новый альбом."
/>
```

Правила, выводимые из кода:

1. `icon` — тематическая Lucide-иконка раздела, часто «пустой» вариант
   (`i-lucide-calendar-x`, `i-lucide-images`, `i-lucide-file-text`).
2. `title` — констатация в прошедшем времени: «Альбомы не найдены»,
   «Мероприятия не найдены».
3. `description` — **что сделать дальше**: «Попробуйте изменить поиск или
   фильтры», «Измените поиск или создайте новый альбом».
4. Пустой результат фильтра и полностью пустой раздел различаются текстом.

### Раздел в разработке — два разных вида

| Вид | Где | Как выглядит |
|-----|-----|--------------|
| `SectionInDevelopment.vue` | `/personnel-reserve`, `/development-motivation` | `UCard` по центру, круг `size-20 bg-primary/10 ring-primary/20`, иконка `i-lucide-construction size-12 text-primary`, заголовок `text-2xl/3xl` |
| Инлайновый `UEmpty` | `/applications` | обычная пустота с `icon="i-lucide-file-text"` |

Два разных решения одной задачи — отклонение, см.
[inconsistencies.md](inconsistencies.md).

## 3. Ошибки

Три механизма, применяются по смыслу. **[ПОДТВЕРЖДЕНО]**

### Toast — результат действия пользователя

Единая обёртка `src/composables/useAppToast.ts` (~35 файлов):

```ts
const { success, error } = useAppToast();
success('Курс опубликован');
error('Не удалось сохранить', 'Проверьте подключение');
```

Оформление задано в обёртке:

| Метод | `color` | `icon` |
|-------|---------|--------|
| `success()` | `success` | `i-lucide-circle-check` |
| `error()` | `error` | `i-lucide-alert-circle` |

Прямой `toast.add({...})` тоже встречается — для нестандартных случаев
(`AdminDashboardPage.vue:880`).

> **Осторожно:** `profileSaved()`, `adminUserSaved()`, `adminOfoSaved()` в этой
> же обёртке содержат текст «(демо)» / «записаны локально», хотя вызываются
> после реального сохранения на сервере. См. [known-issues.md](../known-issues.md),
> IMP-04. Для нового кода используйте `success()`.

### `UAlert` — постоянное предупреждение в контексте

Когда сообщение должно оставаться на экране, а не всплывать:

```html
<UAlert
  v-if="!loading && store.version.value?.status !== 'published'"
  color="warning" variant="subtle"
  icon="i-lucide-alert-triangle"
  title="Курс ещё не опубликован"
/>
```
(`CourseAssignPage.vue:124-130`)

На экране входа — ошибка авторизации:
`color="error" variant="soft" icon="i-lucide-circle-alert"` (`login.vue:100-106`).

### Текст ошибки у поля

Сообщение показывается рядом с полем (см. раздел «Валидация»).

### Ошибки загрузки данных

Composables хранят `error: Ref<string|null>` и **никогда не бросают наружу**:
`fetch` обёрнут в `try/catch`, при сбое возвращается `false` / пустой результат.
Пример — `useNewsData.tryLoadFromApi:37-50`, `usePortalServices.doLoad:100-123`.

Деградация вместо пустого экрана: `usePortalServices` при ошибке подставляет
`FALLBACK_PORTAL_SERVICES`. **[ПОДТВЕРЖДЕНО]**

### Ошибки API

`apiSessionFetch` нормализует ответ в `{ success, message, data }`:
- не-JSON → `{ success: false, message: 'HTTP <код>' }`;
- `!res.ok` без `message` → `Ошибка <код>`;
- 401 после неудачной попытки обновить токен → `Сессия истекла. Войдите снова.`
  **плюс** единый выход на `/login` (см. [auth-and-permissions.md](../auth-and-permissions.md)).

## 4. Успех

| Способ | Когда |
|--------|-------|
| Toast `success()` | Сохранение, публикация, назначение — основной способ |
| Переход | После сохранения профиля — переключение на вкладку стены (`ProfilePage.vue:320`) |
| Флаг `sent` | `FeedbackPage.vue` — экран «сообщение отправлено» вместо формы |
| Обновление списка | `await refresh()` после мутации (`useTestsStore`) |

**Оптимистичные обновления обязаны откатываться при ошибке.** Паттерн из
`AdminDashboardPage.vue:850-882` (после BUG-001/002):

```ts
const prevSnapshot = { ...currentRow };          // снимок
users.value = users.value.map(...)               // оптимистично применили
try {
  const res = await fetch(...);
  const json = await res.json().catch(() => null);
  if (!res.ok || !json?.success) throw new Error(json?.message || `Ошибка ${res.status}`);
  adminUserSaved(...);
} catch (e) {
  if (prevSnapshot) users.value = users.value.map(u => u.id === prevSnapshot.id ? prevSnapshot : u);
  toast.add({ title: 'Ошибка сохранения', color: 'error', description: String(e) });
}
```

**Проверять и `res.ok`, и `json.success`.** `fetch` не реджектит на 4xx/5xx —
именно это было причиной BUG-001/002. **[ПОДТВЕРЖДЕНО]**

## 5. Недоступность

~100 вхождений `disabled` в SFC. **[ПОДТВЕРЖДЕНО]**

| Причина | Как выражается |
|---------|----------------|
| Идёт отправка | `:loading="submitting"` — `UButton` блокируется сам |
| Нет прав | Контрол **не рендерится**: `v-if="canEditSection('...')"` |
| Не выполнено условие | `:disabled="!isValid"` |
| Последовательная разблокировка курса | тема/тест недоступны, пока не пройдено предыдущее |

**Правило проекта: права скрывают контрол, а не блокируют его.** Гейтинг через
`useSectionAccess().canEditSection(...)`. **[ПОДТВЕРЖДЕНО — доминирующий паттерн]**

## 6. Валидация

### Zod + `UForm` — только вход

Единственное место (`login.vue:11-14,98`):

```ts
const schema = z.object({
  login: z.string().min(1, 'Введите логин'),
  password: z.string().min(1, 'Введите пароль'),
});
```

```html
<UForm :schema="schema" :state="state" @submit="onSubmit">
```

`UFormField name="login"` связывает поле со схемой — сообщение появляется
автоматически.

Схемы Zod есть и во втором модуле форм (`src/tests/schemas.ts`), но применяются
императивно в `FormBuilder.vue:5`, не через `UForm :schema`.

### Ручная валидация — все остальные формы

Паттерн `FeedbackPage.vue:31-62`:

```ts
const errors = reactive({ subject: '', message: '' });

function validate() {
  errors.subject = ''; errors.message = '';
  let ok = true;
  if (!form.subject.trim()) { errors.subject = 'Укажите тему'; ok = false; }
  else if (form.subject.trim().length > 200) { errors.subject = 'Тема слишком длинная (до 200 символов)'; ok = false; }
  …
  return ok;
}
```

### Правила текста сообщений

Из существующих формулировок:

| Ситуация | Формулировка |
|----------|--------------|
| Пустое обязательное поле | «Укажите тему», «Введите логин» |
| Слишком коротко | «Сообщение слишком короткое (минимум 10 символов)» |
| Слишком длинно | «Тема слишком длинная (до 200 символов)» |

Правила: обращение на «вы», повелительное наклонение, **лимит указывается в
скобках числом**, без восклицательных знаков.

### Известные ограничения длины

`FeedbackPage.vue`: тема ≤ 200, сообщение 10…5000 символов.

> **Расхождение подходов.** Один экран использует Zod + `UForm`, остальные —
> ручные `reactive`-объекты ошибок. Единого решения нет. См.
> [inconsistencies.md](inconsistencies.md).

## 7. Доступность

### Что фактически сделано

Подсчёт по `src/` на 2026-09-22. **[ПОДТВЕРЖДЕНО]**

| Приём | Вхождений | Комментарий |
|-------|-----------|-------------|
| `aria-label` | 100 | на иконочных кнопках — последовательно |
| `aria-hidden="true"` | 29 | на декоративных иконках и SVG |
| `alt=` | 33 при 27 тегах `<img>` | у всех изображений есть alt |
| `autocomplete` | 7 | в т.ч. `username` / `current-password` на входе |
| `sr-only` | 6 | скрытые подписи (например, вкладки темы) |
| `role="…"` | 4 | точечно |
| `aria-expanded`, `aria-haspopup` | есть | на триггере меню профиля |
| `aria-labelledby` | есть | секции рабочего стола связаны с `<h2>` |

Аудит доступности в [PROJECT_AUDIT.md](../PROJECT_AUDIT.md) имеет статус
**VERIFIED**: «alt у всех `<img>`, `aria-hidden` у декоративных, `autocomplete` в
форме входа, `aria-label` у иконочных кнопок; серьёзных дефектов не найдено».

### Что даёт Nuxt UI бесплатно

Компоненты построены на Reka UI: фокус-ловушки в `UModal`/`USlideover`,
клавиатурная навигация в `UTabs`/`UDropdownMenu`/`USelectMenu`, роли и
`aria-*` у меню и вкладок, видимые кольца фокуса. Поэтому **самописные
интерактивные элементы вместо компонентов библиотеки — прямая потеря
доступности**.

### Обязательные правила

1. Иконочная кнопка без текста → `aria-label` **и** `UTooltip` с тем же
   текстом (подсказка — для мыши, `aria-label` — для скринридера). У триггера
   `UDropdownMenu` подсказку вешают на `span`-обёртку. Исключение — кнопка без
   обработчика: подсказка обещала бы действие, которого нет.
2. Декоративная иконка/SVG → `aria-hidden="true"`.
3. `<img>` → осмысленный `alt` (пустой `alt=""` для чисто декоративных).
4. Секция → `<h2>` + `aria-labelledby` (или `aria-label`).
5. Поля логина/пароля → `autocomplete="username"` / `"current-password"`.
6. Не «гасить» кольцо фокуса. `p-px` у скролл-контейнеров страниц существует
   именно чтобы кольца не обрезались.
7. Не полагаться на цвет как на единственный носитель смысла — дублировать
   иконкой или текстом.

### Чего в проекте нет

- Проверки контраста — **[НЕИЗВЕСТНО]**, автоматической проверки нет;
  при 18 primary-палитрах на выбор контраст гарантирован не для всех сочетаний.
- «Skip to content».
- `prefers-reduced-motion` — анимация смены темы (600 мс) выполняется всегда.
- Автоматических a11y-тестов.
