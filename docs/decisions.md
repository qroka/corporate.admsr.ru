# Журнал архитектурных решений (ADR)

Фиксируются только **подтверждённые** решения: те, что видны в коде, конфигурации,
комментариях, README или аудите. Если причина решения нигде не зафиксирована —
так и написано, домыслы не добавляются.

Формат записи: контекст → решение → подтверждение → следствия.

---

## ADR-001. Параллельная миграция PHP → Go с сохранением URL `/api/*.php`

- **Статус:** действует
- **Решение:** новый backend пишется на Go, но URL-контракты `/api/<имя>.php`
  не меняются. Переключение — точным allowlist'ом nginx
  (`location = /api/<файл>.php` имеет приоритет над регуляркой PHP).
- **Подтверждение:** `backend/README.md` («Vue SPA без изменений… nginx
  переключает маршруты точным allowlist»), `deploy/nginx-corporate.admsr.ru.conf:55-56`,
  `backend/cmd/api/main.go`.
- **Причина (подтверждена):** не менять фронтенд при переносе backend.
- **Следствия:** три списка путей (Go mux, nginx, Vite proxy) нужно держать
  синхронными; для многих эндпоинтов существуют две реализации.
- **Правило переноса, зафиксированное в `backend/README.md`:**
  handler → smoke → nginx allowlist → наблюдение → удаление PHP только после стабилизации.

## ADR-002. PHP-слой заморожен; правки backend — только в Go

- **Статус:** действует с 2026-09-21
- **Решение:** `api/` не изменяется; киоск (`src/pages/Kiosk/`, `AppKiosk`) не
  трогаем. Уже внесённые точечные правки в PHP оставлены как есть.
- **Подтверждение:** `docs/PROJECT_AUDIT.md`, §8 «Решение владельца (2026-09-21)».
- **Следствия:** проблемы SEC-002…SEC-005 остаются открытыми осознанно;
  новая функциональность backend пишется только на Go.

## ADR-003. Личность пользователя берётся только из серверной сессии

- **Статус:** действует
- **Решение:** ни `userId` из тела запроса, ни заголовок `X-User-Id` не являются
  источником личности. Только `auth.Service.CurrentUser` по токену сессии.
- **Подтверждение:** `backend/internal/auth/session.go:159-201`;
  `tests_routes.go` (`viewer()`); `forms.go` (`formsRequireUser`/`formsRequireEditor`);
  `PROJECT_AUDIT.md`, SEC-006/007/008.
- **Причина (подтверждена):** клиентские идентификаторы подделываются — это
  приводило к полному обходу авторизации.
- **Следствия:** клиентский код, всё ещё отправляющий `userId`, — рудимент
  (см. [known-issues.md](known-issues.md), IMP-13). `owner_id IS NULL`
  трактуется как «доступ запрещён».

## ADR-004. Двухканальная передача токена: cookie + Bearer

- **Статус:** действует
- **Решение:** при входе выдаются одновременно httpOnly-cookie `corp_session` и
  `sessionToken` в теле. Сервер принимает `Authorization: Bearer` →
  `X-Session-Token` → cookie в этом порядке.
- **Подтверждение:** `backend/internal/auth/session.go:60-73,108-126`;
  `src/composables/useAuthSession.ts`.
- **Причина (подтверждена частично):** комментарий в `useAuthSession.ts:1-4` —
  «Используется модулем курсов; не ломает legacy API, которые ещё принимают
  userId». То есть Bearer вводился под модуль курсов, cookie осталась для
  легаси-вызовов. Почему не унифицировали позже — **[НЕИЗВЕСТНО]**.

## ADR-005. Проверка прав внутри хендлеров, без middleware

- **Статус:** действует
- **Решение:** `mux.Handle(path, handler)` без цепочек; guard
  (`requireUser`/`requireAdmin`/`requireSection`) вызывается первой строкой
  каждого метода.
- **Подтверждение:** `backend/cmd/api/main.go`, `backend/internal/handlers/section.go`.
- **Причина:** **[НЕИЗВЕСТНО]** — в коде не зафиксирована.
- **Следствия:** забыть guard легко; именно так возникли SEC-001/009. Отсюда
  требование покрывать новые эндпоинты тестом вида
  «аноним → 401 до обращения к БД» (`auth_guards_test.go`).

## ADR-006. Права по разделам через группы портала, плюс суперадмин

- **Статус:** действует
- **Решение:** два независимых уровня — `user_info.user_group = 'admin'`
  (всё) и членство в `portal_access_groups` с правами на `section_key`.
  Для курсов — дополнительное сужение по категории.
- **Подтверждение:** `db/migration/V5`, `V6`; `backend/internal/auth/permissions.go`;
  `src/composables/useSectionAccess.ts`.
- **Следствия:** список секций продублирован во фронте и в Go; синхронизация ручная.

## ADR-007. UI-тоггл роли отделён от прав

- **Статус:** действует
- **Решение:** `localStorage['ui-role']` переключает отображение админ-функций.
  Для суперадмина `canEdit` требует `currentRole === 'admin'`; на права
  обычного пользователя тоггл не влияет.
- **Подтверждение:** `src/stores/role.js`, `src/composables/useSectionAccess.ts:110-118`,
  `src/components/AppHeader.vue:48-58`, `src/router/index.js:280-286`.
- **Причина (выводится из кода):** возможность посмотреть портал глазами
  сотрудника. Явной формулировки в коде нет — **[ЧАСТИЧНО]**.
- **Следствия:** роль в localStorage не является защитой; сервер её не читает.

## ADR-008. Киоск работает без авторизации и без админ-функций

- **Статус:** действует
- **Решение:** ветка `/kiosk` доступна анонимно; роль принудительно `user`;
  `requiresAdmin`/`requiresSection` внутри киоска → редирект на `/kiosk`;
  переходы на «обычные» маршруты из киоска перенаправляются на киоск-аналоги
  **до** проверки авторизации.
- **Подтверждение:** `src/router/index.js:243-277`, комментарий в коде:
  «киоск работает полностью без входа».

## ADR-009. Тема как набор CSS-переменных, применяемых из JS

- **Статус:** действует
- **Решение:** полные палитры Tailwind объявлены в `:root`
  (`src/assets/tailwind.css`), а `applyUiTheme()` копирует выбранную палитру в
  переменные Nuxt UI (`--ui-color-primary-*`, `--ui-color-neutral-*`, `--ui-primary`)
  и задаёт `--font-sans`, `--ui-radius`, `data-ui-font`.
- **Подтверждение:** `src/composables/useUiTheme.ts:186-224`; комментарий там же:
  «Tailwind v4 exposes palette steps as CSS vars… We mirror them into Nuxt UI vars».
- **Причина (подтверждена комментарием в CSS):** палитры объявлены как `:root`,
  «so they are never tree-shaken by Tailwind».
- **Следствия:** доступны 18 primary и 9 neutral цветов, 4 шрифта, 5 радиусов;
  тема применяется до монтирования приложения (`src/main.js`), чтобы не было
  мигания.

## ADR-019. Миграции идемпотентны, без таблицы версий

- **Статус:** действует
- **Решение:** весь SQL пишется как `IF NOT EXISTS` / `ADD COLUMN IF NOT EXISTS`;
  `deploy.sh` прогоняет **все** `V*.sql` при каждом деплое.
- **Подтверждение:** `deploy/deploy.sh:247-259`, текст миграций.
- **Следствия:** новая миграция **обязана** быть идемпотентной, иначе деплой
  сломается на втором запуске.

## ADR-020. Недействительная сессия → единый выход, а не ошибка в интерфейсе

- **Статус:** действует с коммита `bcd9d95` (2026-09-22)
- **Решение:** если авторизованный запрос вернул 401 и повторная выдача токена
  не помогла, приложение один раз уводит пользователя на `/login` с пометкой
  «Сессия истекла», вместо того чтобы показывать ошибку на каждом запросе.
- **Подтверждение:** `src/composables/useAuthSession.ts:64-93,186-191,209-221`
  (комментарий: «Это убирает повторяющуюся ошибку „Требуется авторизация“:
  вместо неё пользователь один раз чисто уводится на страницу входа»);
  `src/composables/useSessionActivity.ts:57-61`; `src/pages/login.vue:28-34`.
- **Причина (подтверждена комментарием):** UX-001 — при истёкшей сессии
  интерфейс выглядел залогиненным и сыпал ошибками.
- **Связанное решение того же коммита:** TTL сессии сделан **скользящим** —
  `CurrentUser` при каждом авторизованном запросе сдвигает `expires_at` на
  полный TTL (`backend/internal/auth/session.go:194-205`). Причина
  (подтверждена комментарием): активный пользователь не должен «отваливаться»
  посреди работы, а реально простоявшая сессия истекает честно.
- **Следствия:** обработчик регистрируется один раз при старте
  (`startSessionActivity`); повторные срабатывания подавляются флагом
  `unauthorizedFired` (сброс через 5 с). Остаток: `check-auth.php` всё ещё
  проверяет флаг `auth`, а не токен.

## ADR-021. «Управление обучением» — отдельная страница, а не вкладка

## ADR-022. Разделители и рамки на `bg-elevated` — `*-accented`

- **Статус:** действует с 2026-09-22
- **Решение:** внутри карточек и панелей с фоном `bg-elevated` рамки и
  разделители — `border-accented` / `ring-accented`, не `*-default`.
- **Подтверждение:** `node_modules/@nuxt/ui/dist/runtime/index.css` — в тёмной
  теме `--ui-bg-elevated` и `--ui-border` оба равны `neutral-800`, а
  `--ui-border-accented` — `neutral-700`.
- **Причина (подтверждена):** `border-default` на `bg-elevated` в тёмной теме
  совпадает с фоном — разделитель невидим (замечено владельцем).
- **Следствия:** на фоне страницы (`bg-default`) `*-default` по-прежнему
  годится. Hover-подсветка внутри `bg-elevated` — `bg-accented/40`, а не
  `bg-elevated/…` (иначе эффекта нет).

## ADR-023. Мастер создания курса — сквозные «Шаг N из 4»

- **Статус:** действует с 2026-09-22
- **Решение:** создание курса (1) → тема (2) → материал (3) → тест темы (4);
  баннеры и тосты между шагами используют одну нумерацию. Флаг режима — `?guide=1`.
- **Подтверждение:** `CourseCreatePage.vue`, `TopicFormPage.vue`,
  `MaterialFormPage.vue`, `CourseAdminTestPage.vue` (строки «Шаг N из 4»).
- **Причина (подтверждена владельцем):** раньше экран создания в нумерации не
  участвовал, но его тост говорил «Шаг 1», и следующий экран встречал вторым
  «Шагом 1 из 3».

## ADR-024. Засчёт времени: файлы и ссылки — без требования фокуса

- **Статус:** действует с 2026-09-24
- **Решение:** heartbeat для `rich_text` идёт, только если вкладка портала
  активна и было действие за 30 с; для файлов и ссылок — пока материал открыт
  и вкладка портала не закрыта.
- **Подтверждение:** `shouldBeat()` в `src/pages/Courses/employee/CourseTopicPage.vue`.
- **Причина (подтверждена владельцем):** файлы и ссылки открываются в новой
  вкладке; при требовании фокуса время на них не шло вовсе, и материал с
  минимальным временем нельзя было пройти, читая его (IMP-20).
- **Следствия:** защита от накрутки — только серверная: `MaterialHeartbeat`
  не засчитывает паузы длиннее 90 с и не добавляет больше 60 с за раз.

## ADR-025. `NextAction` сам завершает «созревшие» темы и не обрывается на просрочке

- **Статус:** действует с 2026-09-24
- **Решение:** (1) если условия темы выполнены, а статус не `completed`,
  `NextAction` завершает тему, пересчитывает блокировки и вычисляет шаг заново;
  то же делает `MaterialHeartbeat` после каждого засчитанного интервала.
  (2) Для `overdue` вычисляется реальный следующий шаг.
- **Подтверждение:** `markTopicCompleted`, `CompleteTopicIfReady`, `NextAction`
  в `backend/internal/courses/common.go`; `MaterialHeartbeat` в
  `backend/internal/handlers/courses.go`.
- **Причина (подтверждена владельцем):** IMP-18, IMP-19 — сотрудник упирался в
  тупик и не мог пройти курс.
- **Следствия:** `NextAction` — чтение **с побочным эффектом** (как и раньше:
  он уже вызывал `RecalculateLocks`). Рекурсия ограничена числом тем:
  повторный вызов происходит, только если `UPDATE` реально изменил строку.

## ADR-026. Порядок тем — перетаскиванием на `vuedraggable`

- **Статус:** действует с 2026-09-24
- **Решение:** в хабе курса темы переставляются перетаскиванием за ручку
  `i-lucide-grip-vertical`; стрелки остались в меню `⋯` для клавиатуры и тача.

- **Подтверждение:** `applyOrder()` в
  `src/pages/Courses/admin/CourseWorkspacePage.vue`; тот же приём —

  `UEditorDragHandle` привязан к Tiptap (`editor: Editor` обязателен);
  `vuedraggable@4.1.0` уже был в зависимостях. Новых библиотек не добавлялось.

## ADR-027. Адаптивность шапки — container queries, а не брейкпоинты окна

  «Поиск…» → полная подпись.
- **Подтверждение:** `src/components/AppHeader.vue` (`ui.root` навбара и три
  `UDashboardSearchButton`); правила есть в собранном CSS
  (`@container (min-width:56rem|72rem)`).
- **Причина (подтверждена владельцем):** ширина шапки зависит от сайдбара —
  его тянут в 220–400px и сворачивают до 0, поэтому брейкпоинт окна `lg:`
  показывал широкий поиск на 340px, когда места уже не было, и тот выдавливал
  хлебные крошки.
- **Следствия:** это первые container queries в проекте. Встроены в
  Tailwind 4, новых зависимостей нет. Размеры контейнеров — стандартная шкала
  Tailwind (`@3xl` 48rem … `@7xl` 80rem).

## Как добавлять запись

1. Решение принято и **видно в коде** — иначе это не ADR, а предложение
   (ему место в [known-issues.md](known-issues.md)).
2. Укажите файл и строку.
3. Причину пишите только подтверждённую. Не уверены — `[НЕИЗВЕСТНО]`.
4. Опишите следствия: что теперь нельзя сделать или о чём нужно помнить.
5. Отменяя решение — не удаляйте запись, пометьте «отменено ADR-NNN».
