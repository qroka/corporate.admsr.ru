## Критичное

### IMP-01. Дамп таблицы пользователей лежит в публичной статике

- **Где:** `public/data/users (1).sql` (≈485 КБ), отслеживается git; та же копия
  уже собрана в `dist/data/users (1).sql`.
- **Что:** SQL-дамп таблицы `users` с колонкой `password`, 10 операторов `INSERT`.
- **Почему критично:** `public/` целиком копируется в `dist/`, а `dist/` — корень
  SPA в nginx (`root /var/www/corporate.admsr.ru/dist`). Специальных правил
  запрета для `/data/` в конфиге нет, SPA-fallback на такой путь не сработает,
  потому что файл существует. То есть файл отдаётся по прямой ссылке любому,
  кто знает путь.
- **Статус:** НАЙДЕНО, не исправлялось. В [PROJECT_AUDIT.md](PROJECT_AUDIT.md)
  не фигурирует.
- **Проверка:** `git ls-files public/data`, `ls dist/data`.
- **Что напрашивается (ПРЕДЛОЖЕНИЕ):** удалить файл из рабочего дерева и из
  индекса git, считать содержащиеся учётные данные скомпрометированными,
  вычистить историю или ротировать пароли. Решение — за владельцем.

## Дефекты и незавершённость реализации

### IMP-02. `GO_VERSION` в деплое старее, чем требует `go.mod`

`deploy/deploy.sh:22` → `GO_VERSION=1.22.10`; `backend/go.mod` → `go 1.26.5`.
На сервере без предустановленного Go автоустановка скачает 1.22.10 и сборка
упадёт. **[ПОДТВЕРЖДЕНО]**

### IMP-03. Стена профиля не сохраняется на сервере

`src/composables/useProfileWall.ts` работает только с
`localStorage['profile-wall-posts:v2']`: ни одного обращения к API. Посты видит
только автор на своём устройстве. UI при этом выглядит как полноценная
социальная стена. **[ПОДТВЕРЖДЕНО]**

Тот же характер у:
- RSVP мероприятий — `events-rsvp:v1` (`useCalendarFeed.ts:37`);
- личных записей календаря и встреч — `portal-calendar-local:v1`
  (`useCalendarFeed.ts:36`).

### IMP-04. Тексты уведомлений говорят «демо», хотя сохранение реальное

`src/composables/useAppToast.ts`: `profileSaved()` — «Изменения записаны локально
(демо)»; `adminUserSaved()` — «(демо)»; `adminOfoSaved()` — «изменения записаны
локально (демо)».

Все три вызываются **после успешного ответа сервера**:
`ProfilePage.vue:315` (после `POST /api/profile.php`),
`AdminDashboardPage.vue:874` (после `PUT /api/users.php`), `:508`, `:575`.
Пользователю сообщается неправда. **[ПОДТВЕРЖДЕНО]**

### IMP-05. Кнопка «Уведомления» ничего не делает

`src/components/AppHeader.vue:315-324` — `UButton` с иконкой `i-lucide-bell`,
без `@click`, без `to`, без выпадающего меню. **[ПОДТВЕРЖДЕНО]**

### IMP-06. `forceLogout` не чистит токен сессии

`useSessionActivity.ts:48-56` удаляет `auth-user` и `auth-last-check`, но
оставляет `auth-session`. `clearAuthStorage()` (`useAuthSession.ts`, выход по
кнопке) чистит все три. Разное поведение двух путей выхода: после авто-логаута
в localStorage остаётся мёртвый токен. **[ПОДТВЕРЖДЕНО, HEAD `bcd9d95`]**

### IMP-07. ~~Незамкнутая цепочка обработки 401~~ — ЗАКРЫТО

Закрыто коммитом `bcd9d95`. `triggerUnauthorized()` вызывается из
`apiSessionFetch` (`useAuthSession.ts:190`) и из обеих веток `apiSessionUpload`
(`:210`, `:219`); обработчик регистрируется в `useSessionActivity.ts:61`.
Защита от повторов — флаг `unauthorizedFired` со сбросом через 5 секунд.

Тем же коммитом TTL сессии сделан **скользящим** (`auth/session.go:194-205`).

Остаток UX-001 не закрыт: `check-auth.php` по-прежнему проверяет флаг
`user_info.auth`, а не валидность токена —
см. [auth-and-permissions.md](auth-and-permissions.md).

### IMP-08. `tailwind.config.js` не подключён и содержит опечатку

Проект на Tailwind CSS 4: конфигурация живёт в `src/assets/tailwind.css`
(`@import "tailwindcss"` + `@theme`), директивы `@config` нет, значит
`tailwind.config.js` PostCSS-плагином не читается.

Дополнительно в самом файле — `scerrm: { '3xl': '1700px' }` вместо `screens`.
Реальный брейкпоинт `3xl` задан в `tailwind.css:5` (`--breakpoint-3xl: 1700px`).
**[ПОДТВЕРЖДЕНО]**

### IMP-09. `@heroicons/vue` в зависимостях, но не используется

Ни одного импорта в `src/`. Иконки — Lucide через `UIcon`. **[ПОДТВЕРЖДЕНО]**

### IMP-10. Иконки загружаются с внешнего CDN

`UIcon` → `@iconify/vue`, который при отсутствии локально зарегистрированных
коллекций тянет данные с `https://api.iconify.design`
(`node_modules/@iconify/vue/dist/iconify.mjs:632`). В проекте нет ни пакета
`@iconify-json/lucide`, ни вызова `addCollection`. Используется ~850 иконок
Lucide.

Для интранет-портала это означает зависимость отрисовки иконок от доступа во
внешнюю сеть. Подтверждено чтением кода; **фактическое поведение в прод-сети не
проверялось**. **[ЧАСТИЧНО ПОДТВЕРЖДЕНО]**

### IMP-11. В корне репозитория лежат посторонние файлы

`tash` (3.2 КБ) и `diff.txt` (17 КБ) — сохранённые вывода `git diff`,
отслеживаются git. **[ПОДТВЕРЖДЕНО]**

### IMP-12. Неиспользуемый компонент с префиксом `U`

`src/components/UContentSurround.vue` — 0 использований в проекте. Имя с
префиксом `U` совпадает с соглашением Nuxt UI, что может ввести в заблуждение
(это компонент проекта, а не библиотеки). **[ПОДТВЕРЖДЕНО]**

### IMP-13. Рудиментарный `userId` в теле запросов модуля тестов

`src/composables/useTestsStore.ts` продолжает слать `userId: currentUserId()` в
`tests_list/save/publish/delete/unpublish/direct/submit/participant`. Сервер эту
величину игнорирует (исправление SEC-008), но код создаёт ложное впечатление,
что личность передаётся клиентом. То же с заголовком `X-User-Id` в
`src/tests/api.ts:22`. **[ПОДТВЕРЖДЕНО]**

### IMP-14. Схему нельзя развернуть с нуля

`db/migration/` не создаёт `user_info`, `news`, `events`, `gallery`,
`gallery_base`, `ofo_*`, `absence_journal`, `portal_feedback`. Эти таблицы
считаются уже существующими (комментарий `V1__init_schema.sql:10-11`:
«In this project there is already public.user_info (legacy)»). Скрипта их
создания в репозитории нет. **[ПОДТВЕРЖДЕНО]**

### IMP-15. Нет проверки типов TypeScript

57 файлов `.ts` и десятки SFC с `lang="ts"`, но `tsconfig.json` отсутствует.
Vite/esbuild только срезают типы, не проверяя их. Ошибка типа попадёт в прод
незамеченной. **[ПОДТВЕРЖДЕНО]**

## Раздел «Обучение»: найдено при UI-доработке 2026-09-22…24

В отличие от записей выше, эти дефекты найдены **в ходе доработки раздела** и
большинство исправлено в той же задаче — статус указан у каждой записи.
Проверка исправлений: `npm run build`, `go build/vet/test`; **живьём не
проверялось** — БД `172.17.4.21:5432` была недоступна, Go API не стартовал.

### IMP-16. «Тем: 0» в админском списке курсов — выдуманное число

- **Где:** `src/pages/Courses/admin/CoursesListPage.vue` (было `c.topicsCount ?? 0`).
- **Что:** поле `topicsCount` не отдаёт ни Go (`MapCourseRow`,
  `backend/internal/courses/common.go:113`), ни PHP — у каждого курса
  выводилось «Тем: 0».
- **Статус:** ИСПРАВЛЕНО — счётчик убран из карточки. Настоящее число тем в
  список не приходит; чтобы его показывать, нужна правка `List` в Go.

### IMP-17. `"<nil>"` вместо пустых полей в списке курсов

- **Где:** `backend/internal/handlers/courses.go:162` — `fmt.Sprint(row["short_description"])`
  и `fmt.Sprint(row["ver_status"])` на NULL дают строку `"<nil>"`.
- **Статус:** ОБОЙДЕНО на фронте — `cleanText()` в
  `src/composables/useCoursesStore.ts`. В Go остаётся.

### IMP-18. Просроченный курс — тупиковая кнопка «Просрочен дедлайн»

- **Где:** `NextAction`, `backend/internal/courses/common.go` (ветка `case "overdue"`).
- **Что:** для `overdue` возвращался `{type:'overdue'}` без `topicId`; главная
  кнопка на странице курса ничего не делала. При этом курс проходим:
  `TryCompleteEnrollment` статус не проверяет, `AttemptStart` пускает `overdue`
  (`backend/internal/handlers/tests_routes.go:1321`).
- **Статус:** ИСПРАВЛЕНО в Go — для `overdue` считается реальный следующий шаг.
  Фронт на `type==='overdue'` не был завязан (проверено grep'ом).

### IMP-19. Тема с минимумом времени застревала навсегда

- **Где:** статус темы → `completed` только в `MaterialComplete`
  (`courses.go`), `AttemptFinish` (`tests_routes.go`), `TryCompleteEnrollment`.
- **Что:** если минимум времени **темы** набирался после отметки последнего
  материала, статус никто не пересматривал; `RecalculateLocks` держал следующую
  тему закрытой, `NextAction` отдавал `complete_topic`, для которого нет эндпоинта.
- **Статус:** ИСПРАВЛЕНО в Go — `markTopicCompleted` / `CompleteTopicIfReady`
  в `common.go`; самолечение в `NextAction` (завершает тему и пересчитывает шаг)
  и проверка после каждого heartbeat (ответ содержит `topicCompleted`).
  `EnrollmentProgress` теперь вызывает `NextAction` до подсчёта тем.

### IMP-20. Время на файлах и ссылках не засчитывалось

- **Где:** `src/pages/Courses/employee/CourseTopicPage.vue`, heartbeat.
- **Что:** файл/ссылка открываются в новой вкладке, а heartbeat требовал
  `document.hasFocus()` — время не шло, «Отметить изученным» получала 409.
- **Статус:** ИСПРАВЛЕНО — для файлов и ссылок фокус не требуется (решение
  владельца, см. [decisions.md](decisions.md), ADR-024).

### IMP-21. Сбои в цикле прохождения темы

- **Где:** `src/pages/Courses/employee/CourseTopicPage.vue`.
- **Что:** (а) после отметки материала `data` перезаписывался ответом темы без
  списка тем — пропадала кнопка «К следующей теме» и название курса в крошках;
  (б) при ошибке загрузки — пустой экран; (в) «К следующей теме» показывалась,
  даже если сервер тему не засчитал → 403; (г) минимум времени не был виден,
  «Отметить изученным» отвечала 409.
- **Статус:** ИСПРАВЛЕНО.

### IMP-22. Статус `failed` никогда не выставляется

- **Где:** Go и PHP только читают `failed` (`common.go`, `api/courses_common.php:1275`),
  присваивания нет.
- **Следствие:** ветки «Не сдан» в интерфейсе — мёртвые; при провале итогового
  теста курс остаётся `in_progress`.
- **Статус:** ОТКРЫТО. Нужно ли состояние «не сдан» — вопрос к владельцу.

### IMP-23. Неиспользуемые поля в API прохождения

- `TopicGet` всегда отдаёт `nextTopic: nil` (`courses.go`, ответ `TopicGet`) —
  фронт строит переход сам по списку тем.
- Поле `seconds` в теле heartbeat сервер игнорирует — считает интервал по
  `last_heartbeat_at`.
- **Статус:** ОТКРЫТО, на поведение не влияет.

### IMP-24. `fullDescription` курса больше нигде не заполняется

- **Где:** поле есть в типе `CourseVersion`, в Go (`courses.go`, `contentKeys`)
  и в БД. Экран создания его больше не пишет; настройки его никогда не
  редактировали; ни один экран его не показывал.
- **Статус:** ОТКРЫТО — решить, удалять поле или выводить описание сотруднику.

### IMP-25. Дефекты админки курсов, закрытые попутно

Все — ИСПРАВЛЕНО:
- `/admin/courses` была заглушкой-редиректом на `/courses?tab=manage`, крошки
  мигали скелетоном → отдельная страница (ADR-021);
- группа `failed` не отображалась в «Моём обучении», при одних `failed` —
  «Вам ничего не назначено»;
- хаб курса при ошибке загрузки — пустой экран без выхода;
- удаление темы без флага отправки — возможен повторный запрос;
- настройки курса сохраняли пустое название (проверялась только категория);
- материал типа «Файл» создавался без файла, «Ссылка» — с пустым URL;
- страницы формы темы/материала/теста при ошибке загрузки показывали пустую
  форму, создание темы уходило с `versionId: undefined`;
- пустой список категорий делал форму создания курса неотправляемой без
  объяснения.
