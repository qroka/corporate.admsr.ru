## Критичное

### IMP-01. Дамп таблицы пользователей лежит в публичной статике

- **Где:** `public/data/users (1).sql` (≈485 КБ), отслеживается git; та же копия
  уже собрана в `dist/data/users (1).sql`.
- **Что:** SQL-дамп таблицы `users` с колонкой `password`, 10 операторов `INSERT`.
- **Почему критично:** `public/` целиком копируется в `dist/`, а `dist/` — корень
  SPA в nginx (`root /var/www/corporate.admsr.ru/dist`). Специальных правил
  запрета для `/data/` в конфиге нет, SPA-fallback на такой путь не сработает,
  потому что файл существует. То есть файл отдаётся по прямой ссылке любому,
  кто знает путь.
- **Статус:** НАЙДЕНО, не исправлялось. В [PROJECT_AUDIT.md](PROJECT_AUDIT.md)
  не фигурирует.
- **Проверка:** `git ls-files public/data`, `ls dist/data`.
- **Что напрашивается (ПРЕДЛОЖЕНИЕ):** удалить файл из рабочего дерева и из
  индекса git, считать содержащиеся учётные данные скомпрометированными,
  вычистить историю или ротировать пароли. Решение — за владельцем.


> **Статус (2026-09-25): УБРАН ИЗ РЕПОЗИТОРИЯ** — `git rm "public/data/users (1).sql"`,
> каталог `public/data/` удалён, в свежей сборке `dist/data/` нет. На сервере файл
> перестанет отдаваться **после следующего деплоя** (`npm run build` пересоздаёт `dist/`).
> **Остаётся за владельцем:** дамп есть в истории git — вычистить историю
> (`git filter-repo`) и считать пароли из дампа скомпрометированными: сменить их.

## Дефекты и незавершённость реализации

### IMP-02. `GO_VERSION` в деплое старее, чем требует `go.mod`

`deploy/deploy.sh:22` → `GO_VERSION=1.22.10`; `backend/go.mod` → `go 1.26.5`.
На сервере без предустановленного Go автоустановка скачает 1.22.10 и сборка
упадёт. **[ПОДТВЕРЖДЕНО]**

> **Уточнение и статус (2026-09-25): ИСПРАВЛЕНО** — `GO_VERSION` по умолчанию
> `1.26.5` в `deploy/deploy.sh:22` и `deploy/deploy.env.example`.
> - Go ≥ 1.21 при `GOTOOLCHAIN=auto` сам докачивает нужную версию, так что
>   «упадёт» верно для сервера без доступа к `proxy.golang.org` или с
>   `GOTOOLCHAIN=local`. **[НЕ ПРОВЕРЕНО на сервере]**
> - **На сервере:** `deploy/deploy.env` в `.gitignore` — если он скопирован из
>   старого примера, там осталось `GO_VERSION=1.22.10`, и правка по умолчанию
>   не подействует. Обновить вручную.
> - Если `/usr/local/go` уже установлен, `deploy.sh` его версию **не
>   проверяет** (`deploy.sh:268`) — старая установка останется. Не исправлялось.

### IMP-03. Стена профиля не сохраняется на сервере

`src/composables/useProfileWall.ts` работает только с

Тот же характер у:

- личных записей календаря и встреч — `portal-calendar-local:v1`

### IMP-04. Тексты уведомлений говорят «демо», хотя сохранение реальное

`src/composables/useAppToast.ts`: `profileSaved()` — «Изменения записаны локально
(демо)»; `adminUserSaved()` — «(демо)»; `adminOfoSaved()` — «изменения записаны
локально (демо)».

Все три вызываются **после успешного ответа сервера**:
`ProfilePage.vue:315` (после `POST /api/profile.php`),
`AdminDashboardPage.vue:874` (после `PUT /api/users.php`), `:508`, `:575`.
Пользователю сообщается неправда. **[ПОДТВЕРЖДЕНО]**

> **Поправка 2026-09-25.** Утверждение выше верно только для первых двух.
> `saveOfoEdit()` (`AdminDashboardPage.vue:507`) и `saveOfoPositions()` (`:573`)
> к серверу **не обращаются вовсе** — форма ОФО ничего не записывает, а тост
> «ОФО сохранено» был ложным в обратную сторону.
>
> **Статус: ИСПРАВЛЕНО.** `profileSaved()` и `adminUserSaved()` — без
> «(демо)». `adminOfoSaved()` заменён на `adminOfoNotSaved()`: предупреждение
> «Изменения не сохранены — редактирование ОФО пока не подключено к серверу».
> Попутно в `ProfilePage.vue` отказ сервера больше не глотается молча: при
> `!res.ok` / `!success` и при сетевой ошибке — тост `error()`.
> **Открыто:** само редактирование ОФО — подключить к Go или скрыть кнопки
> (решение владельца, Q-07).

### IMP-06. `forceLogout` не чистит токен сессии

`useSessionActivity.ts:48-56` удаляет `auth-user` и `auth-last-check`, но
оставляет `auth-session`. `clearAuthStorage()` (`useAuthSession.ts`, выход по
кнопке) чистит все три. Разное поведение двух путей выхода: после авто-логаута
в localStorage остаётся мёртвый токен. **[ПОДТВЕРЖДЕНО, HEAD `bcd9d95`]**

> **Последствие и статус (2026-09-25): ИСПРАВЛЕНО.** Проблема была не только
> косметической: `getSessionToken()` (`useAuthSession.ts:8`) предпочитает
> `auth-session` токену из `auth-user`, а вход перезаписывает его, только если
> сервер вернул `sessionToken` (`login.vue:52`). Иначе после повторного входа
> курсы слали бы мёртвый токен. `forceLogout` теперь вызывает
> `clearAuthStorage()`; отметка «Сессия истекла» в `sessionStorage` не затронута.

### IMP-16. «Тем: 0» в админском списке курсов — выдуманное число

- **Где:** `src/pages/Courses/admin/CoursesListPage.vue` (было `c.topicsCount ?? 0`).
- **Что:** поле `topicsCount` не отдаёт ни Go (`MapCourseRow`,
  `backend/internal/courses/common.go:113`), ни PHP — у каждого курса
  выводилось «Тем: 0».
- **Статус:** ИСПРАВЛЕНО полностью (2026-09-25). Сначала счётчик убран из
  карточки, затем `List` в Go стал отдавать настоящее `topicsCount` (подзапрос
  по `course_topics` текущей версии без удалённых). Карточка показывает «N тем»,
  ноль — предупреждающим цветом («нет тем»: такой курс нельзя опубликовать).
  Если поля в ответе нет (старый бинарник), счётчик не выводится.

### IMP-17. `"<nil>"` вместо пустых полей в списке курсов

- **Где:** `backend/internal/handlers/courses.go:162` — `fmt.Sprint(row["short_description"])`
  и `fmt.Sprint(row["ver_status"])` на NULL дают строку `"<nil>"`.
- **Статус:** ИСПРАВЛЕНО в Go (2026-09-25) — хелпер `textOrNil` в
  `backend/internal/handlers/courses.go` отдаёт `null`. Страховка `cleanText()`
  в `src/composables/useCoursesStore.ts` оставлена до обновления бинарника на
  сервере. Остальные `fmt.Sprint(row[...])` в ответах курсов проверены по схеме
  (`V4__courses_module.sql`) — там колонки `NOT NULL`.

### IMP-18. Просроченный курс — тупиковая кнопка «Просрочен дедлайн»

- **Где:** `NextAction`, `backend/internal/courses/common.go` (ветка `case "overdue"`).
- **Что:** для `overdue` возвращался `{type:'overdue'}` без `topicId`; главная
  кнопка на странице курса ничего не делала. При этом курс проходим:
  `TryCompleteEnrollment` статус не проверяет, `AttemptStart` пускает `overdue`
  (`backend/internal/handlers/tests_routes.go:1321`).
- **Статус:** ИСПРАВЛЕНО в Go — для `overdue` считается реальный следующий шаг.
  Фронт на `type==='overdue'` не был завязан (проверено grep'ом).

### IMP-19. Тема с минимумом времени застревала навсегда

- **Где:** статус темы → `completed` только в `MaterialComplete`
  (`courses.go`), `AttemptFinish` (`tests_routes.go`), `TryCompleteEnrollment`.
- **Что:** если минимум времени **темы** набирался после отметки последнего
  материала, статус никто не пересматривал; `RecalculateLocks` держал следующую
  тему закрытой, `NextAction` отдавал `complete_topic`, для которого нет эндпоинта.
- **Статус:** ИСПРАВЛЕНО в Go — `markTopicCompleted` / `CompleteTopicIfReady`

### IMP-29. `deploy.sh` хранится в git с окончаниями CRLF

- **Где:** `git show HEAD:deploy/deploy.sh` — CR в конце всех 498 строк;
  `.gitattributes` в репозитории нет.
- **Почему важно:** деплой делает `git pull` на Linux-сервере. Скрипт с CRLF
  обычно не запускается (`/usr/bin/env: 'bash\r'`, `set: pipefail\r: invalid
  option`).
- **Противоречие:** портал в проде обновляется, значит, на сервере это как-то
  обойдено (другие настройки git, `dos2unix`, запуск не из git) — из
  репозитория не видно. **[НЕИЗВЕСТНО]**
- **Предложение:** `.gitattributes` с `*.sh text eol=lf` и перенормализация
  файла. Не делалось: меняет весь файл и способ, которым сервер его получает, —
  сначала выяснить, как деплой запускают сейчас.
- **Статус:** ОТКРЫТО.

### IMP-30. Срок прохождения нельзя было задать из портала

- **Где:** `CourseAssignPage.vue` слал `deadlineAt: null` жёстко; `defaultDeadlineDays`
  версии не редактируется ни на одном экране. Go (`Assign`) поддерживает все три
  способа: `deadlineAt`, `deadlineDays`, `defaultDeadlineDays`.
- **Следствие:** у назначений из портала срока не было, статус «просрочен» не
  возникал, весь интерфейс сроков у сотрудника фактически не работал.
- **Попутно:** «Дата начала» уходила строкой `datetime-local` без часового пояса;
  Go разбирает RFC3339, не узнавал её и отсчитывал дни от текущего момента.
- **Статус:** ИСПРАВЛЕНО (2026-09-25) — в форме назначения поле «Пройти до»
  (уходит как ISO конца выбранного дня), даты отправляются в ISO с поясом,
  проверка «не в прошлом» и «не раньше начала». **Открыто:** поле
  `defaultDeadlineDays` в настройках курса. Нюанс для правки: тело запроса Go
  декодирует числа в `float64` и пишет в integer-колонку как есть — проверить
  на живой БД.

### Q-11. Назначение и результаты по ОФО — только корневые подразделения

Форма назначения (`CourseAssignPage.vue`, `ofoItems`) предлагает только
